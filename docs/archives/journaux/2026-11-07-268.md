# 2026-11-07 — #268 : les écrans des projets et des registres réservés suivent le rôle sur le périmètre

<sub>[← Archives](../readme.md)</sub>

- **Quoi** : le chef de projet calculé par l'interface (`useIsLead`, qui remplace `isLead`)
  vaut gestionnaire **du périmètre du projet** ou responsable désigné ; le bouton de création
  d'un registre réservé aux gestionnaires (services, SLA, évaluations NIS 2) et l'encadré
  « Découverte » d'un CI se montrent au gestionnaire d'au moins un périmètre.
- **Pourquoi** : PER-06 et ADR-0014 D4 (le rôle par périmètre prime sur le rôle AD), PRJ-04 ;
  l'API tranchait déjà ainsi (`ProjectRights.IsLead`, `RecordController.CanCreate` sur le
  périmètre choisi, sas de découverte filtré sur les périmètres gérés). Un User AD
  gestionnaire du Siège voyait « Lecture seule » sur un projet qu'il pouvait modifier ; un
  Manager AD simple User recevait 403 derrière un bouton affiché. Suite de #219 et #220.
- **Fichiers** : `frontend/src/modules/project-management/rights.js`,
  `components/Overview.jsx`, `components/Agile.jsx`, `components/Registers.jsx`,
  `frontend/src/core/components/RecordList.jsx`,
  `frontend/src/modules/service-configuration-management/pages/ConfigurationItemDetail.jsx`,
  `frontend/src/core/useManagerOn.test.jsx`, `frontend/src/core/useManagesPerimeter.test.jsx`
- **Documentation** : aucune référence à changer (PER-06 et PRJ-04 décrivent déjà la règle)
- **Commit** : correction de #268
